Study A · one GPU

Prefill: what one mixer block costs, 1k to 1M tokens

One mixer block at d_model 4096 on one B300, batch 1, with everything the block runs: projections, short conv, the scan or attention kernel, norms and the output projection. Attention is the FlashAttention-4 schedule (two Q tiles ping-ponging, tcgen05 MMAs, accumulators in TMEM). Mamba-2 is the five Triton kernels of mamba_chunk_scan_combined. Linear attention runs on the same SSD kernels with d_state = d_k = 128 and headdim = d_v = 128; Gated DeltaNet adds the per-chunk K Kᵀ and WY passes.

  • Attention wins until about 15k tokens. At 1k it is 2.4× cheaper than scalar-gated linear attention and 3.5× cheaper than Mamba-2. The recurrent blocks pay for their projections and for SSD kernels that run Triton tl.dot tiles at a fraction of tcgen05 peak; attention runs on the tensor cores at 1.1 to 1.4 PFLOP/s.
  • Crossovers: scalar linear attention passes GQA attention at about 15k tokens, Gated DeltaNet at about 22k and Mamba-2 at about 32k. Mamba-2 crosses last because the 8B Mamba-2 block is wider (expand 2: an 18,560-wide in_proj, which is 45% of its block time at 16k).
  • At 1M tokens one attention block takes 6.5 s, quadratic and tensor bound at 1.38 PFLOP/s. The linear blocks take 0.17 to 0.27 s, 24× to 37× less. MLA prefill is 1.44× attention at every long length: its 192-wide QK heads do 1.5× the score FLOPs.

Study B · kernel and rack

Decode attention: GQA, MQA, GTA, MLA and GLA

Decode attention reads the KV cache once per token, so what decides it is how many cache bytes each rank reads and whether the kernel can stream them at HBM speed. The variants keep Llama-3-70B's body and change only attention. The cache size per token per layer is GQA-8 2048 elements, GTA-8 1088 (one tied state per group plus a shared 64-wide RoPE key), MLA 576, GLA-2 576 (two 256-wide latents plus RoPE), and MQA 256. Under tensor parallelism the picture changes. MLA's single latent cannot be split, so every rank reads all 576. GLA's two latents split over TP2, and GQA's 8 heads split down to one per rank at TP8.

  • The FA4-style decode kernel is latency-bound for grouped heads. A decode CTA pads its 8 real query rows to a 128-row tile, and one softmax warpgroup chains QK → softmax → PV for every K/V block. Halving the bytes (GTA) therefore bought only 4 to 9% in that schedule. A FlashMLA-style schedule, with two warpgroups splitting each block so that one's softmax overlaps the other's MMA (added to the simulator as kv_warpgroups: 2), makes GTA-8 1.2 to 1.3× faster than GQA-8 at every TP degree. It still reaches only 4.1 to 4.7 TB/s, against 5.3 to 6.6 for GQA.
  • MLA under TP is the expensive case. At TP8 a rank reads 576 elements per token for MLA, 320 for GLA-2 and 256 for GQA-8 or MQA. Per layer that is 93 µs for MLA, 45 µs for GLA-2 and 25 µs for GQA-8 (16 sequences × 16k). GLA-2 halves MLA's decode attention once TP ≥ 2, which is the paper's point. In this Llama-70B body, though, GQA-8 at TP8 already caches less per rank than GLA-2.
  • On the rack the cache decides the batch. On GB300 NVL72 at 8k context with TP8 replicas, the most throughput per GPU comes from GTA-8 (1,701 tok/s/GPU at batch 512), then GQA-8 and MQA (1,474), GLA-2 (910) and MLA (433, where only batch 256 fits). At 128k context GTA-8 leads by 22% (144 vs 118 tok/s/GPU). MLA fits only 16 sequences per replica there and delivers 32 tok/s/GPU.

The MLA decode kernel is the weakest point of this study. Its 576-wide latent leaves room for only 32-wide K/V blocks in the synthetic kernel (Q tile plus two stages in 228 KB of shared memory), so it runs at about 400 TFLOP/s at TP1. FlashMLA uses 64-wide blocks and reports about 660 TFLOP/s on H800. Read the MLA points as pessimistic.

Study C · GPU, node, rack

One long prompt over 72 GPUs: ring attention vs state passing

Each 8B-class model prefills one prompt with context parallelism and no tensor parallelism. Attention layers run zig-zag ring attention: each rank holds two sequence chunks, does its causal diagonal, then passes K/V around the ring for 71 steps, with every step overlapping one transfer with half a chunk of attention. Mamba-2, linear attention and Gated DeltaNet layers pass state instead: each rank scans its chunk locally, receives the final state from the rank before it, folds it in, sends it on, and corrects its own outputs with one small GEMM. The hybrid is three Gated DeltaNet layers per attention layer. All of it is explicit per-rank programs on the simulated NVLink fabric. The only shortcut is that kernels over 8k² attention or 32k tokens run on the fast path described under Method.

  • At 144k tokens on 72 GPUs, ring attention is bound by NVLink. Each rank holds only 2,048 tokens, so a ring step's attention is shorter than its K/V transfer. GQA reaches 24.5% MFU and 179 ms. GTA puts half the bytes on the ring and cuts TTFT by 28%, to 128 ms. The hybrid has only 8 attention layers, yet they still make it 2.6× slower than pure Gated DeltaNet (88 vs 34 ms).
  • From 576k tokens the ring is compute-bound. GTA and GQA are within 0.5% at 576k and both reach 44% MFU, rising to 49% at 1.13M. Attention's quadratic work now dominates everything, so the recurrent models win by the ratio of total FLOPs: at 1.13M tokens GQA takes 4.42 s, Mamba-2 0.28 s (15.8× less), Gated DeltaNet 0.25 s (17.7×) and scalar linear attention 0.24 s (18.7×). The 3:1 hybrid takes 1.30 s (3.4× less than GQA).
  • State passing costs almost nothing. A rank waits for one state per layer from its predecessor, and the serial chain across 72 ranks moves only 1 to 3 ms of transfers in total. Mamba-2 and Gated DeltaNet scale from 1 GPU to 72 GPUs at 144k by 64× and 66×. GQA scales only 32× (5.74 s → 0.18 s) and the hybrid 36×, because their rings stall on transfers.
  • Node vs rack. At 144k the HGX node (8 GPUs, 18k tokens per rank) is compute-bound for every model, and GQA and GTA are equal there (765 vs 760 ms). Going from 8 to 72 GPUs at 1.13M speeds up GQA by 7.9× and Gated DeltaNet by 9.2×. Long prompts use the whole rack well; short prompts stall on the ring.

Method

How these numbers were made

  • Hardware: the calibrated B300 SM model (148 SMs, measured clocks, caches, HBM, tcgen05 rates, DVFS under the power cap, launch gaps), with main's PR #17 memory fixes. Kernel-level points run on one GPU of the HGX B300 preset. Study B's rack runs and Study C's 72-GPU runs use GB300 NVL72 (the same die, NVLink 5 through NVSwitch); the 8-GPU runs use HGX B300. No GPU was used for this page. Everything here is the simulator, and the single-GPU model is validated against Nsight Compute elsewhere in the repository.
  • Long-context fast path (rackscale.extrap). A causal FA4 forward over 16k tokens takes about 6 minutes to simulate on this 4-core machine, and 1M tokens would take days. Long attention kernels are therefore simulated at cycle level on reduced grids that are an exact number of full waves, with 16 and 32 K/V iterations per CTA, and extrapolated as waves × (a + b·iterations). GEMMs, norms, convs and SSD stages are fitted linearly in tokens. GEMMs are fitted only past the power model's largest measured run, because the sustained clock depends on kernel size (an earlier rule that ignored this was 5.6% fast). In a rack run, the long kernels become fixed-duration ops, and the SMs held by concurrent ring transfers are taken off their wave count. The table below compares the fast path with full runs.
  • Approximations: Gated DeltaNet is SSD plus two extra passes, and the delta rule's sequential d_k × d_k correction between chunks is not modelled. The context-parallel lowering does not exchange the 3-token conv halo. Ring attention uses zig-zag chunks, so every off-diagonal step does half a chunk. Attention kernels do not get the power-cap clock drop that GEMMs get (logged as an open gap in docs/CALIBRATION.md), so long attention is slightly optimistic against the GEMMs around it.
