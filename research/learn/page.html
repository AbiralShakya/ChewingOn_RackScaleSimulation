Communication primitives

An all-reduce leaves every GPU with the sum of everyone's buffer. A ring does it in 2(n−1) steps, each GPU sending 1/n of its buffer to its neighbour per step: 2(n−1)/n · B bytes per GPU in total. NVLS (NVLink SHARP) lets the switch do the adding: each GPU writes its buffer into the switch once and reads the sum back once, B bytes each way, at the same time. That is why the formula for an all-reduce halves on NVL72.

The roofline, and why it moves

A kernel can go no faster than its FLOPs at peak or its bytes at HBM bandwidth. Arithmetic intensity (FLOPs per byte) says which: below the ridge at C/β ≈ 361 FLOP/byte a kernel is memory bound. A decode GEMM's intensity is about its batch, so decode is weight-bandwidth bound until roughly 361 sequences. The lower roof is the B300's measured clock under its power cap (1455 vs 2032 MHz): long training GEMMs run there.

Pipeline bubbles

With pipeline parallelism each GPU holds a few layers and micro-batches flow through. A stage waits at the start for the first micro-batch to reach it and at the end for the last gradient to come back: the bubble, (p−1)/(m+p−1) of the step for GPipe and 1F1B. Zero-bubble scheduling (ZB-H1) splits the backward pass into input gradients (B) and weight gradients (W) and moves the W work into the gaps. These timelines are the ideal replay of the lowered program: Llama-3-8B cut to 8 layers, 4 stages, 8 micro-batches of 4k tokens.

Several models on one rack

Each tenant is a model with its own plan and GPUs, lowered on its own and placed on the shared NVLink fabric. On an NVL72 each GPU has its own link to each of the 18 switch chips, so tenants on different GPUs do not slow each other. Traffic between them (KV caches into a decode pool) costs what it occupies, and tenants sharing a GPU pay for every SM, cache line and byte of HBM bandwidth they share. Book chapter 12 has the formulas.

Tokens vs bytes

A byte-level model reads raw bytes instead of BPE tokens (about 4.45 bytes each in English), so a naive one does 4.45× the steps. H-Net (Hwang, Wang, Gu, 2025) learns where to cut: small Mamba-2 encoders read every byte, a router marks chunk boundaries (about one per 4.7 bytes), and only the chunks reach the large main network. Per byte of text, the FLOPs come out close to a BPE Transformer's. Decode is where it gets interesting: the main network runs only on the steps where a sequence's router fires, so the batch it sees changes every step.
