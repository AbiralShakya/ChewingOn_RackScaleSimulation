Dense models from 1B to 405B parameters, mixture-of-experts from 3B to 37B active, four attention designs, Mamba-2 and a hybrid, contexts to 128k, on HGX A100, HGX H100, HGX B300 and GB300 NVL72. Every point is a simulated decode step, prefill or training step: each distinct kernel runs at cycle level on the SM model, every collective runs on the simulated NVLink fabric, and the step is split into what it was waiting on.

Use it as a tool

Everything on this page comes from two commands. rackscale plan answers one question with a machine-readable result, so a script or an agent can call it in a loop: change a model dimension, a system or a target and read back the best layout and what bounds it.

# best layout for Qwen3-235B decode on an NVL72 at 30 tokens/s per user, as JSON
rackscale plan qwen3-235b-a22b --system gb300 --context 8192 --min-tps-user 30 --json

# a custom grid, or one of this page's studies
rackscale sweep --models llama3-8b,llama3-8b-mla --systems b300 --contexts 8192,131072 --batches 1,64
rackscale sweep --study moe --jobs 8 -o moe.json

# rebuild this page
python research/model_sweep/run.py && python research/model_sweep/build_page.py

The same is available from Python as rackscale.sweep (best_plan, run, study_points, pareto).

How to read these numbers

A kernel counts as compute-bound when its tensor pipe runs at half of peak or more, HBM-bound when it moves HBM bytes at half the achievable bandwidth or more, and latency-bound when it reaches neither (too few CTAs, wave tails, dependency chains, barriers). Comm is collective time not hidden behind kernels and launch is the GPU sitting idle between kernels. Throughput assumes every replica of a layout matches the simulated one, which holds for TP and for EP under balanced routing.
